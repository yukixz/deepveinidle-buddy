# 大额预估金额与异常隔离

状态：已实现，版本与发布状态见[当前状态](../../status.md)。常用规则已整合至[计算与显示](../../panel.md#计算与显示)，本文保留数值边界与验收依据。

## 问题与目标

行情校验已经接受超过 1B 的单价。收藏候选在分页前计算所有目标档位的材料成本，金额累计却与数量共用 `Number.MAX_SAFE_INTEGER` 上限。一行超限后抛出 `quantityOverflow`，渲染层捕获整次候选计算失败，留下空列表。

利维坦之鳞（355）用于利维坦护符（配方 306）。从零到千万收藏档需要 1,000 万片鳞，单价 1B 时仅鳞片成本即为 `10^16`，超过安全整数上限约 `9.007 × 10^15`；其他材料成本会进一步降低触发单价。该边界取决于收藏缺口、材料需求和报价，并非固定 1B。

目标是让正常的大额估算继续参与显示、排序、筛选、订单和采购汇总；真正无效的金额结果只阻断相关金额，不清空整张候选表。

## 数值规则

所有数值继续使用 JavaScript `Number`，不引入 BigInt 或十进制定点库。预估金额接受浮点误差，不承诺逐金币精确；超过安全整数上限不等于不可估算，不以该上限截断金额。

| 数值用途 | 规则 |
| --- | --- |
| 材料成本、产物价值、采购金额、已知价格小计、费用、建议售价及其合计 | 有限且非负，允许超过 `Number.MAX_SAFE_INTEGER`；每次金额乘加后校验结果 |
| 金币／点及其他金额派生效率 | 有限且非负；计算前确认分母有限且大于零，不将非法分母转为零成本 |
| 实际制造／采购数量、物品与配方标识、存档 revision | 保留现有整数、安全范围及业务校验 |
| 期望次数、期望材料／产物数量、时间、精通点 | 保留现有数值范围与业务规则，本次不放宽 |
| 行情单价、用户输入的费用与费率、持久化筛选阈值 | 保留现有输入、存储校验和上限；只放宽计算所得金额及其派生值 |
| 游戏草稿数量与单价 | 保留安全整数、游戏上限及读回一致性检查；估算总价不作为交易输入 |

缺价仍为未知，明确的零报价仍为零。金额仅在格式化显示时按既有规则舍入，排序、筛选与半成品比价使用未格式化数值；不增加用于改变路线选择的近似相等容差。

## 无效金额与界面行为

1. 将 `NaN`、`Infinity`、负数等非法金额结果明确标记为「金额不可计算」，与「缺价」区分。已接受的大额有限金额正常显示，不标成溢出。
2. 候选的金额计算失败只影响该行金额及其派生效率，保留名称、目标、材料、时间、精通点和管理操作。该行保留在无金额上限的结果中；金额排序时不可计算值与缺价值同置末尾，沿用稳定次序。有金额上限时，这两类值均不能确认满足条件，应排除。
3. 行内显示失败原因，避免把金额不可计算呈现成「无匹配配方」。只隔离已识别的金额错误；配置、数据结构及其他程序错误继续明确报告，不使用宽泛 catch 掩盖。
4. 订单与采购金额复用相同规则。依赖失败金额的合计显示不可计算，不把有效部分冒充完整合计；独立数量、动作与有效金额仍可展示。缺价时既有「已知价格小计」规则保留，但不得跳过无效金额后将其当作正常小计。
5. 金额失败本身不禁止加入、移出、调整收藏目标或预填有效动作。采购草稿依旧由有效的单件报价与采购数量决定；数量、单价或计划依赖无效时继续按现有守卫停止。

## 实现范围

- 抽取简单的金额校验与乘加函数，避免重复判断；共用 `add()`、`safeAdd()` 等数量逻辑保留原有约束，逐处按用途替换金额调用。
- 覆盖 `app` 收藏候选、`crafting-estimates` 单次估值及半成品路线、`workspace` 订单／采购／费用汇总。避免只修表格而在加入计划后再次失败。
- 调整 `collection-sorting` 和通用数值排序的调用方式，使金额列接受大额有限浮点数，数量列继续按现有范围校验。检查筛选与输入的单位换算，不扩大持久化阈值范围。
- 显式传递缺价与无效金额状态；复用现有返回结构时仅增加必要字段，不以零值、超大哨兵数或一个无法区分原因的 null 替代错误。
- 用户存档保持 `version=2`，不增加持久化字段，不迁移旧存档；原始行情及用户输入的合法范围保持不变，上游生成文件不改动。

## 验收

1. 利维坦之鳞单价 1B、1.1B，角色可制作利维坦护符且收藏缺口为千万档时，候选表保留全部符合条件的行，显示大额成本与金币／点。以独立算式核对结果，浮点比较采用与量级相称的误差容限。
2. 覆盖安全整数上限附近及以上的乘积、多个材料相加后超限；验证这类有限金额不再报 `quantityOverflow`。
3. 大额金额的金币／金币每点升降序、金额阈值、翻页、技能／品质／搜索筛选及全部加入订单均保持一致；包含大额行但当前页未显示时也正常。
4. 单次制造成本、产物估值、半成品自制比价、订单材料成本、费用、建议售价和采购汇总都接受大额有限金额，不在后续环节再次拒绝。
5. 人工构造金额乘加产生非有限值：只标记受影响金额及依赖合计，其他候选正常；金额排序置末、阈值排除、管理操作可用。负值和非法分母明确失败；缺价与零报价语义保持。
6. 超安全范围的实际次数／采购数量、非法单价与存档计数继续拒绝，验证没有放宽共用数量校验；草稿预填仍核对整数值与游戏接受范围。
7. 运行相关计算、排序、费用、工作区与预填回归；因金额汇总跨多个共用模块，实现后运行完整单元测试，并用浏览器合成夹具验证表格和计划。真实账号与移动真机结果单独记录，不以合成验证替代。
